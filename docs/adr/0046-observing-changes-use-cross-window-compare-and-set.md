# Observing changes use cross-window compare-and-set

Main and Capture each own an AppSettings instance, so a per-window queue cannot prevent a concurrent configuration save from erasing a successful Pause. Every Observing replacement goes through a Rust command that compares the raw stored value and persists its replacement under one process-wide mutex; a conflict returns the current value so AppSettings can reapply its pure TypeScript transform, with the original change instant and at most eight attempts. The window-local queue still orders that window's changes, failures still release it, and announcements follow successful persistence only. This is settings write sequencing, not session state (ADR 0025); other settings keys and in-flight Observe sweeps are outside this decision.

Retries can encounter state produced at a later instant. A repository addition therefore inherits every overlapping Pause after its original addition instant, including a Pause that has already ended; a Pause uses consent history to include repositories that were removed after its original instant. Keeping these temporal rules in the Observing core preserves excluded work without moving the Pause forward to retry time.

An application ACL gates all custom commands once any application permissions exist. The established Desktop commands retain their previous grants to local app windows through one explicit permission; Observing alone receives the new Main/Capture grant. A real MockRuntime IPC test uses the generated ACL to verify handler access, while a source accounting test keeps the established command grant aligned with registration.
