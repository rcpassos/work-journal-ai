# A Project Mapping files what arrives

Observed Notes arrive filed. A **Project Mapping** names one repository — by its identity, the common directory every worktree of it shares, never the directory the user picked — and the Project its Notes are filed under, held in the journal as one row per repository rather than in the settings file, because it decides the filing of Notes and a Backup has to carry it. ADR 0007 survives intact: a mapping is a *value on the mapping*, naming a Project by the same rule a Note's Project obeys (stored lowercase, letters, digits, `_` and `-`), so there is still no registry — a name nothing holds is gone. No mapping is Unfiled, and Unfiled is a real state rather than a mapping to nothing: the field on the repository's row starts empty, the repository's own name is offered as the first completion, and it becomes the Project only when the user picks or types it. Nothing is ever inferred from a path, and a mapping decides how work *arrives*: an Observed Note the user refiles by hand stays where they put it, and no later sweep moves it. Renaming or merging a Project rewrites the Notes and the mappings in one operation, so nothing afterwards distinguishes a merged mapping from a filed one. Rejected: keeping the mapping in the settings store (it decides journal content, and a Restore that lost it would silently unfile a repository); deriving the Project from the repository name at add time (offering the name is enough — picking it is the user's decision, and a directory name is not a Project name); carrying the mapping inside the Note's Body (ADR 0007 put Project beside the Body precisely so filing is not markup inside it, and a Body is editable forever); giving the mapping's own Settings row the rename question (rename is one question about one stream, asked in one place).

## Consequences

A Project held only by a mapping outlives the last Note under it: it stays discoverable in the Filter and in completion, and stays renameable and mergeable, because its repository still files there. That reaches the empty journal too — with no Notes at all there is no Filter to carry the name, so History loads the Projects independently of the opening range and its empty state names them, with the same rename question the Filter's pencil asks. Without it, a first-run user who maps a repository before capturing anything would hold a Project they can neither see nor rename. A mapping keys on the repository rather than on a directory, so two worktrees of one repository file under one Project; a repository taken off the Observing list leaves its mapping behind, the same way its consent is kept, so adding it again resumes the filing it had.
