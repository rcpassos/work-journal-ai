# Observing selects branch refs per repository

Observing may read several branches per repository; an explicit empty selection reads all locally available branch refs. Default-branch-only observation missed Chronos work on `develop` while `main` waited for a release (#335). Branches are chosen as exact local or remote-tracking refs, so a local branch and its remote counterpart remain distinct choices even when one is stale. Discovery excludes symbolic remote HEAD aliases and tags, never fetches, and never changes the repository.

Selected tips are walked together along first-parent: a shared commit hash is read once, and the journal's existing repository/hash event identity continues to prevent duplicate Notes across sweeps, branch changes, and deletion. Missing selected refs are retained and explained; available selections still work, and losing every selection never falls back to all branches. Rewritten and squash-merged commits with different hashes remain distinct events. This deliberately broadens version 0.16.1's default-branch-only policy; it does not infer that two commits describe the same work.

Older settings with no branch field retain their previous default-branch policy until the user changes the selector. New repositories start with an explicit empty selection, whose all-branches meaning the control explains. Rejected: interpreting an absent legacy field as all branches, which would unexpectedly create permanent Notes from unfinished branch work after an update; treating an empty selection as no observation, which contradicts the requested control; choosing the checked-out branch implicitly, which makes observation depend on checkout changes.
